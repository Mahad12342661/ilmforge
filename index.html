Behind the Message

Your message travels further than you think. Discover how encryption protects it.

Encryption scrambles a message with a secret key so that only the person who holds the right key can unscramble it. Anyone who grabs the message on the way sees only meaningless data. This site runs real encryption (ECDH, HKDF and AES-256-GCM) inside your browser, so you can watch every step.

    Key Concepts

    Plaintext

    The original, readable message, such as "Meet me at 5pm".

    Public key

    A value you can share openly. Others use it to set up a secret with you, and it does not reveal your private key.

    Private key

    A value you never share. Only its owner can use it to complete the key agreement.

    ECDH

    Elliptic-Curve Diffie-Hellman. Two people swap public keys and each combines the other's public key with their own private key, arriving at the same secret without ever sending it.

    Shared secret

    The identical value Alice and Bob each compute. It is raw material, so HKDF turns it into a proper encryption key.

    AES-256-GCM

    A fast, widely used cipher with a 256-bit key. The "GCM" mode also adds a tag that detects tampering.

    Initialisation vector (IV)

    A random, single-use number that makes every encryption unique. It is public, but must never be reused with the same key.

    Ciphertext

    The scrambled output that looks like random data. It is safe to send across an untrusted network.

    Decryption

    Reversing encryption with the correct key and IV to recover the plaintext. A wrong key or altered data makes it fail.

    Why can't an eavesdropper read the message?

    An interceptor sees only the two public keys, the IV and the ciphertext. Without a private key they cannot compute the shared secret, so they cannot derive the AES key. Guessing a 256-bit key is computationally impossible, and any change to the ciphertext makes GCM decryption fail.

    An honest limitation

    This demo assumes Alice and Bob have authenticated each other's public keys, meaning each knows the key truly belongs to the other. ECDH alone does not prevent a man-in-the-middle attack: an attacker who swaps in their own public keys could read everything. Real systems prove identity with certificates, signatures or key fingerprints.
